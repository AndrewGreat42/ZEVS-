# Учёт задач и рабочего времени

## Инструменты

- **GitHub Issues** — задача, владелец, срок, критерии готовности и ссылка на реализацию.
- **GitHub Projects** — отдельная канбан-доска (создаётся вручную в GitHub). Колонки: `Backlog`, `Todo`, `In Progress`, `Review`, `Done`.
- **`../../time/time-log.csv`** — время, фактически потраченное на задачу; файл попадает в репозиторий.
- **`budget.md`** — плановая трудоёмкость по участникам, а не фактические часы.

## Процесс

1. Создать Issue по задаче из `backlog.md` и назначить владельца.
2. Переместить задачу в `In Progress`.
3. Создать ветку `feature/<issue>-<slug>`, реализовать изменение.
4. После рабочей сессии добавить строку в CSV с фактическими часами.
5. Создать PR, указать `Closes #<номер>` и результаты тестов.
6. После ревью слить PR, закрыть Issue и отметить `Done`.

## Формат файла

```csv
date,github_user,issue_number,activity,hours
```

Строка соответствует одной реальной рабочей сессии. Дата — `YYYY-MM-DD`; часы — десятичное число с точкой (например, `1.50`). **Не вносить фиктивные работы или плановые часы вместо фактических.**

Пример формата записи:

```csv
2026-10-20,example-user,14,Настройка Docker,1.50
```
