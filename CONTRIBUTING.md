# Правила работы команды

1. Каждая задача оформляется в GitHub Issues с номером из [docs/management/backlog.md](docs/management/backlog.md), исполнителем, оценкой и критерием приёмки.
2. Ветки: feature/номер-название, fix/номер-название.
3. Изменения интегрируются через Pull Request, просматриваемый другим участником.
4. В описании PR указывать связанный Issue и результат проверки.
5. После реальной рабочей сессии вносить время в [time/time-log.csv](time/time-log.csv).
6. Не коммитить .env, пароли, токены, настоящие персональные данные гостей, папки target или node_modules.
7. Изменения бизнес-логики должны отражаться в docs/requirements/requirements.md, docs/requirements/business-rules.md и docs/design/api.md.

Готовность задачи: результат работает, тесты пройдены, документация актуальна, PR просмотрен, время записано.
