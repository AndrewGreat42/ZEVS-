## Порядок взаимодействия

- Все задачи заводятся в GitHub Issues; один Issue — одна проверяемая задача.
- Каждый Issue имеет исполнителя, приоритет, критерии готовности и плановые часы.
- Работа ведётся в ветке по задаче, внесение в `main` — через Pull Request после проверки другим участником.
- Фактические рабочие часы фиксируются в `time/time-log.csv`.
- Команда проводит еженедельную короткую встречу и обновляет статус задач.
- Изменение объёма MVP согласуется с руководителем и отражается в требованиях.
